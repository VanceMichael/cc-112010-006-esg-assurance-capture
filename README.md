# 交易所披露与独立鉴证

所有企业、组织、采购条件和鉴证记录均为合成资料。来源显示时间使用带时区的业务时间。

使用 Node.js 22.23.4。执行 `npm ci` 后运行 `npm start`，资料源默认监听本机 4173 端口，可用 `PORT` 指定端口。

`GET /exchange` 和 `GET /verifier` 是可浏览的资料入口。`GET /ready` 或 `GET /health` 返回当前发布序号和总发布次数。`PUT /replay` 接受 JSON `{"step":1}`，用于在联调时将来源切到指定发布时刻。发布序号从 0 开始。每次发布只列变化的来源，应答沿用上一轮存在且未被替换的地址。收到 404 并不代表之前的历史资料从业务上被撤回。重新启动服务从第 0 次发布开始。

/exchange 为交易所 HTML 目录，文书详情的页号对应来源页脚号。更正页用 old 与 new 文书编号说明变化，carry 页中的锚点依然按旧版披露身份读取。/verifier 发布机构文件，撤回链接会保留原文件身份与适用范围。/assets 提供组织与场址的标识关系。采购要求与已发采购决定分别在 /requirements 和 /issued。

机构目录的 rel=next 指向继续页。同一栏目录前页打不开某个详情时，其他已可跟随的项继续可读。data-event=notice 是撤回预告，正式范围与生效时间由其详情提供，不能使用预告的目录时间代替。

运行 `npm test` 可校验资料源实际应答。样本内容存放在 `samples/`，开发时通过各来源的本地地址进行联调。

## 披露证据采集与评审

`cli.mjs` 是采集与评审入口，证据库默认写在 `data/store.json`（可用 `--store` 指定）。

```sh
node cli.mjs collect [--origin http://127.0.0.1:4173] [--at 时间]   # 采集一轮
node cli.mjs review --as-of 2026-03-12                              # 按评审基准日求值
node cli.mjs issue T2 --on 2026-04-22T10:00+08:00                   # 全部满足才发结论并冻结证据
node cli.mjs decision Q1                                            # 打开决定书：当时证据与需复核的变化
node cli.mjs site S-01 [--as-of 2026-03-12]                         # 场址视图：声明/覆盖/漏取/新增分列
```

采集与评审遵循的口径：

- 文书按披露编号与机构文件号归并，不按标题或下载文件名去重；更正公告的 replace/carry 边用来定位现行正文，延用内容领不回时登记缺口留给评审员。
- 正文里挂的审验函链接只记为企业自称；是否覆盖以机构文件写明的组织、场址、期间、指标口径为准，合计与逐场址数字不替换，部分范围鉴证不按整体已审验处理。
- 基准日可见性只看来源标明的发布时间；本次首次取得时间另记，用于标识“披露时已存在但本次漏取”的补录候选。索引不再展示某文件不推定撤回。
- 撤回预告本身不调整资格：正式文件未领齐时，依赖该证明的门槛送回核对并暂停发新结论；正式文件领回后按其写明的范围与生效时间调整，未涉及的部分继续可用。
- 已发出的决定冻结当时证据；后来的更正、撤回或范围收缩不反改决定，但决定书会列出变化，且当前评审不再把失效范围列为已证实。
